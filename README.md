# CvDsl — a compiler for a custom CV language

A domain-specific language for writing CVs and a compiler that turns a `.cv` file into a single, self-contained, print-ready HTML page (and optionally PDF). Built in **Java** with **ANTLR v4**, together with a VS Code tooling setup: syntax highlighting, snippets, one-key build and in-editor error reporting.

Authors: **Filip Sobala**, Bartłomiej Przytuła — Compiler Theory course project, AGH Kraków.

## Example input
```text
CV_START

CONFIG {
    THEME: "Modern-Dark"
    ACCENT_COLOR: "#4CAF50"
    EXPORT_PDF: TRUE
}

SECTION Personal_Info {
    NAME: "Filip Sobala"
    EMAIL: name@example.com
}

SECTION Experience {
    WORK_HISTORY: [
        {
            COMPANY: "Tech Corp"
            POSITION: "Software Engineer"
            START_DATE: 2024-07
            END_DATE: PRESENT
            RESPONSIBILITIES:
                - "Designed internal configuration languages."
                - "Optimized the parsing engine."
            TECH_STACK: ["Java 21", "ANTLR v4"]
        }
    ]
}

CV_END
```
`CONFIG` controls the look of the output (theme, accent color, photo, PDF export) without touching the document structure.

## Compiler architecture
```
.cv file
  → CvDslLexer      (generated by ANTLR from CvDsl.g4)   token stream
  → CvDslParser     (generated by ANTLR)                 parse tree
  → CvBuilder       (extends CvDslBaseVisitor<Node>)     own AST
  → Cv.toHtml()     (recursive rendering)                output_<name>.html (+ .pdf)
```
- **Own AST, separate from ANTLR's parse tree.** `CvBuilder` maps grammar rules to a `Node` hierarchy: `Cv`, `ConfigNode`, `SectionNode`, `FieldNode`, `ObjectNode`, `ListNode` and typed values (`StringNode`, `NumberNode`, `BooleanNode`).
- **Every node renders itself** (`interface Node { String toHtml(); }`), so arbitrarily nested lists and objects render with no special-case code.
- **Separation of concerns:** grammar = syntax, `CvBuilder` = domain model, `Node` classes = presentation. A new output format (e.g. Markdown) only needs new render methods.
- **All CSS is generated in one place** from `ConfigNode`, so the output is a single file with no external stylesheets.

## Error reporting
- **Syntax errors:** a custom `CvErrorListener` attached to the lexer and the parser prints errors as `file:line:column: error: message`.
- **Semantic checks** in `CvBuilder`: duplicate section names, and required `NAME` / `EMAIL` fields in `Personal_Info`, reported in the same format.
- A VS Code **problem matcher** parses this format, so errors show up as red underlines and clickable entries in the Problems panel.

## VS Code tooling
- **`cvdsl` extension:** syntax highlighting mapped 1:1 to the grammar tokens, auto-closing brackets, auto-indent, code folding, comment toggling.
- **Snippets:** `cvdoc`, `section`, `field`, `bullets`, `objlist`, `multiline`, `experience`.
- **One-key build:** a VS Code task bound to `F6` compiles the currently open `.cv` file with Maven and opens the generated HTML in the browser.

## Language reference
**Tokens:** `CV_START`/`CV_END`, `CONFIG`, `SECTION`, `IMPORT`, keys (`NAME:`), strings, multiline `"""..."""`, dates (`2024-07`), `PRESENT`/`NOW`, URLs, e-mails, phone numbers, numbers, `TRUE`/`FALSE`, `#` and `/* */` comments.

**Grammar** (`Kompilator_CV_do_HTML/src/main/antlr4/CvDsl.g4`):
```antlr
cv_document  : T_START import_stmt* config_block? section+ T_END ;
import_stmt  : T_IMPORT T_STRING ;
config_block : T_CONFIG T_LBRACE pair* T_RBRACE ;
section      : T_SECTION T_LABEL T_LBRACE content* T_RBRACE ;
content      : pair | list_field | object_list | bullet_list ;
pair         : T_KEY value ;
list_field   : T_KEY T_LSQUARE (value (T_COMMA value)* T_COMMA?)? T_RSQUARE ;
bullet_list  : T_KEY (T_DASH value)+ ;
object_list  : T_KEY T_LSQUARE (object_block (T_COMMA object_block)* T_COMMA?)? T_RSQUARE ;
object_block : T_LBRACE content* T_RBRACE ;
value        : T_STRING | T_MULTILINE | T_DATE | T_YEAR | T_PRESENT
             | T_URL | T_EMAIL | T_PHONE | T_NUMBER | T_BOOLEAN ;
```

## Build and run
Requires Java and Maven.
```bash
cd Kompilator_CV_do_HTML
mvn compile exec:java -Dexec.args="src/main/resources/test.cv"
```
The output is written to `output_test.html`. Without an argument the compiler uses `src/main/resources/test.cv`.
